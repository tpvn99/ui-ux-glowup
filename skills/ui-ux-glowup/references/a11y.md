# Accessibility — WCAG 2.2 AA

Two layers. `audit.mjs` covers what can be read from the page (contrast, alt, labels, accessible names, focus ring, tap targets, zoom, reduced motion). `a11y.mjs` covers behaviour:

```bash
node <skill-dir>/scripts/a11y.mjs <page|url> [--json a11y.json]
```

Read-only. It presses Tab up to 60 times, checks ARIA and landmarks, then reloads at 320 px. Each finding has a fix; exit 1 on errors.

| Rule | Severity | WCAG | Fix |
|---|---|---|---|
| `keyboard-trap` | error | 2.1.2 | Let Tab leave the widget |
| `focus-obscured` | error | 2.4.11 (new in 2.2) | `scroll-padding-top` = sticky header height |
| `focus-order-jumps` | warning | 2.4.3 | DOM order = reading order |
| `no-focusable` | error | 2.1.1 | Real `<a href>`, `<button>`, inputs |
| `role-not-focusable` | error | 2.1.1 | Native element, or `tabindex="0"` + Enter/Space |
| `aria-invalid-role` | error | 4.1.2 | A role that exists, or a native element |
| `aria-broken-reference` | error | 4.1.2 | `aria-labelledby` / `describedby` ids must exist |
| `aria-hidden-focusable` | error | 4.1.2 | Use `inert` instead (inert content is ignored) |
| `dialog-no-name` | error | 4.1.2 | `aria-labelledby` → the dialog title |
| `auth-paste-blocked` | error | 3.3.8 (new in 2.2) | `autocomplete="current-password"`, no `onpaste` block |
| `reflow-320` | error | 1.4.10 | No fixed widths; grids need `grid-cols-1` (Tailwind) so columns can shrink |
| `no-skip-link` | warning | 2.4.1 | First element: skip link to `#main`, visible on focus |
| `no-main-landmark` | warning | 1.3.1 | Wrap the content in `<main>` |
| `autoplay-no-pause` | warning | 2.2.2 | Visible pause control |
| `duplicate-id`, `positive-tabindex`, `table-no-headers` | warning | 4.1.2, 2.4.3, 1.3.1 | Unique ids; tabindex 0/-1 only; `<th scope>` |

Horizontal scrolling inside a deliberate scroller (tabs, data table) is allowed and not reported.

## Modals and menus: write a scenario

The script can't open what needs a click. For each dialog, drawer and menu add a scenario (`testing.md`): open it, `{ "expect": { "focusWithin": "[role=dialog]" } }`, `Tab` and `Shift+Tab` stay inside, `Escape` closes, and `{ "expect": { "focusOutside": "[role=dialog]" } }` after closing returns focus to the trigger.

## By hand — what no script proves

- **Screen reader pass** (VoiceOver, NVDA) on the primary journey: names, order, announced errors and status messages (4.1.3).
- **Zoom 200 %** and text spacing: nothing clipped or overlapping.
- **Pointer alternatives**: anything dragged also works with clicks (2.5.7).
- **Consistent help** (3.2.6): contact or help link in the same place on every page.

A clean report means these checks found nothing, not that the page is conformant. Say what was not tested.
